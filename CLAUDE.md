# Working rules for Claude (PhishNet)

Read this file before starting any task in this repository.

## Efficiency
- Be extremely efficient and conservative with tokens and usage.
- Keep output direct and concise. Avoid broad file dumps and unrelated refactors.
- Read only the files needed. Prefer targeted greps and line ranges.

## Git commits and PRs
- Commit messages: one sentence only.
- No co-author lines. Do not add `Co-Authored-By` to commits.
- PR descriptions: do not include "Generated with Claude Code", "Generated by Copilot", or any similar attribution.
- Commit or push only when the user approves.
- Give git commands one by one, not chained, when instructing the user.

## Live Monitoring workflow
- Plan: `docs/live-monitoring.md`. Do not implement until the user approves the plan.
- Implement in phases. After each phase: pause, share work completed and work remaining, and give simple, step-by-step manual tests. Wait for approval before committing.
- Phase order: (1) backend, (2) app flow, (3) notifications, (4) provenance badges (deferred), (5) Gmail end-to-end verification, (6) Yahoo cleanup, then docs and legal copy last.
- Do not implement History filtering.
- Do not enable schedules until Gmail, FCM, deep-link, and disconnect flows are verified end-to-end.
- Never store Gmail tokens on-device. Never log credentials or email content.
- Safe emails must not alert. High-risk alerts must be deduplicated and actionable.
- Preserve unrelated worktree changes. Inspect branch and remote state before any history rewrite.

## Documents
- README status updates are allowed to keep status accurate. Mark items Done only when verified. Include no sensitive data.
- Legal and product copy (privacy policy, Terms) changes only after Gmail verification.
